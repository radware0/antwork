# Architecture

antwork is a Windows app with a React 19 and TypeScript interface bundled by a small esbuild script. The five app screens use hash navigation. The website has a separate download-page entry point and static documentation. Rubik carries the interface; Tailwind v4 and the existing theme-token CSS coexist without a global Tailwind reset. Retained profile avatar primitives use Base UI. The chart uses a registry-installed EvilCharts ECharts line chart in a lazy ESM chunk. The dock adapts the supplied minimal source; the top-bar Black/White switch adapts the supplied Bencho liquid toggle using the existing Motion dependency. Applicable source licenses are documented in the repository's third-party notices. Motion is short, stateful, and disabled or reduced when the operating system requests less motion.

## Local data flow

The app loads one document from IndexedDB database `work-ledger`, store `documents`, key `current`. UI changes go through a repository interface: load, update, and replace. Updates validate and normalize the full document before writing in a read-write transaction. A BroadcastChannel tells other open tabs when local data changes. There is no HTTP API or server-side session data in this beta.

The refreshed v1.1.0 build uses JSON backup schema version 7. It contains profile identity and cropped images, campaigns, sessions, daily journals, timer state, timer-panel preferences, username-onboarding completion, sound preferences, shared day-card backgrounds, any older per-date media awaiting replacement, and retained legacy quest/target records. Timer-panel preferences hold the optional normalized background image, image opacity and blur, and preferred width and height. Imports from versions 1 through 4 receive timer defaults; an existing handle marks onboarding complete. Version 5 preserves timer customization and prompt completion. Versions 1 through 5 acquire an empty per-date background map, and versions 1 through 6 acquire empty shared slots. Version 6 retains its whole per-date media collection. Versions 1 through 7 normalize to the current shape. Older quest-linked work is attributed to a campaign when that relationship can be found. Saved System and Slate appearance normalize to Black, saved White remains White, and older muted sound preferences remain muted. No database or store rename is required. v1.0.0 and the original v1.1.0 build cannot import schema-7 backups.

Daily ratings are stored separately from journals and session ratings in `dailyRatings`, with one Good, Steady, or Rough value per date. `calendarMode` persists the shared display preference. These additions use schema-version-5 defaults: backups without them load an empty rating map and Day quality mode. Both fields survive current backup exports and imports.

`dayCardPreferences` stores two nullable background slots and a nullable active index. Each slot holds a normalized WebP image or bounded MP4/WebM video data URL. The selected slot is used for all dates; without a selection, older per-date media in `dayCardBackgrounds` remains visible until replacement. The first shared save clears that old map only after user confirmation and a backup export offer. Validation rejects more than two slots, selection of an empty slot, and mixed shared/legacy collections.

Videos are rendered through temporary blob URLs, compatible with the existing desktop media CSP. File selection verifies decoding and duration; imports decode every shared and legacy asset, including inactive choices. Backup validation also checks dates, types, headers, payload sizes, and duration metadata. Card totals use saved sessions only. Repository writes measure UTF-8 bytes using the same formatted serialization as JSON export and reject growth beyond 32 MiB. Over-limit legacy reads and reductions remain allowed. Media stays in the existing document and is stored once rather than copied across dates.

## Time model

An interval session holds one or more precise timestamp ranges. Local-midnight splitting assigns its duration to each calendar day it touches. A duration session instead holds a date and whole minutes, with no fabricated clock times. Shared session calculations feed the calendar, charts, campaign totals, career stats, and Score. Active timer time is shown provisionally but saved totals wait for session settlement. Countdown recovery uses persisted timestamps and a transaction winner so two open tabs do not both settle or alarm for the same timer.

## Windows wrapper

Electron serves the production UI and documentation through the secure `antwork://app` custom protocol. A checked path resolver limits requests to bundled files. The renderer uses a sandbox, context isolation, a restricted Content Security Policy, and no Node integration. HTTP/HTTPS links open in the system browser. Documentation opens in a separate window without the privileged bridge, leaving the timer renderer mounted. The timer pop-out reuses the timer view and IndexedDB repository, synchronizing changes through the existing BroadcastChannel. Both timer windows can persist native pause requests; only the main window reports the recovery heartbeat and countdown deadline. Minimize hides the main window in the tray. Hidden renderers stop their clock interval and use Chromium background throttling; a single native timeout wakes the main renderer when a countdown is due. Visibility restoration refreshes the clock immediately. Closing the pop-out leaves the main session active. A single-instance lock prevents another desktop app instance from operating on the same profile.

The narrow preload bridge exposes timer lifecycle messages and a command to open local documentation. Sleep and close first write a native pause checkpoint, then request an IndexedDB update. Close is acknowledged after the transaction commits. A five-second close fallback retains the checkpoint if the renderer is unresponsive. Every mutation checks pending pauses before changing data or settling a countdown. Minimize and screen lock leave timers running; sleep, close, and recovery require manual resume. A five-second heartbeat bounds crash recovery to the last durable timestamp, which may discard up to five seconds of unconfirmed work. Browser timer behavior is unchanged.

The NSIS installer supports current-user or all-users installation and a chosen application directory. Earlier 0.1.x builds used Squirrel.Windows. The stable data profile remains under `%APPDATA%\antwork`; uninstall preserves it and manual updates reuse it. Main/preload code and their licenses are bundled before packaging, and the package excludes development source and local configuration.

## Boundaries

The app rejects JSON backup files above 32 MiB before reading them and validates imported records, images, links, dates, and durations. This is a beta guard, not comprehensive protection against resource-heavy but smaller files; record counts and free-text lengths in legacy imports do not have universal caps. These local checks are not server rate limits. Browser storage can be cleared or lost; JSON export is the only backup path today. The architecture deliberately keeps a repository boundary for later sync, but account identity, authorization, encrypted content upload, and server resource controls are not implemented.
